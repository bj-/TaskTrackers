# Workflow: Разработчик / Тестировщик по задаче

Автоматически заполняет кастомные поля **Разработчик** и **Тестировщик**.

## Правила

| Файл | Когда срабатывает | Что делает |
|---|---|---|
| `set-on-assign.js` | Меняется Assignee (сам взял задачу или тимлид назначил), либо задача создаётся сразу с исполнителем | Пишет исполнителя в «Разработчик» или «Тестировщик» в зависимости от роли. При `OVERWRITE_ON_ASSIGN = true` перезаписывает поле при переназначении |
| `set-on-work-item.js` | В задачу списано время | Если соответствующее поле **пустое** — пишет туда автора списания |

Снятие исполнителя поля не очищает — история «кто делал» сохраняется.

## Как определяется роль

1. Группа пользователя (`DEVELOPER_GROUPS` / `TESTER_GROUPS`) — основной способ.
2. Если пользователь не в группах или в обеих сразу:
   - для списания времени — тип работы (`DEVELOPER_WORK_TYPES` / `TESTER_WORK_TYPES`);
   - затем состояние задачи (`DEVELOPER_STATES` / `TESTER_STATES`).
     Для отдельных проектов набор состояний задаётся в `PROJECT_STATES` — например, в проекте «Тестирование»
     (внутренний проект группы тестирования) «В работе» тоже означает тестировщика.
     Группа всё равно важнее: участник группы «Разработчики» и там попадёт в «Разработчик».
3. Если роль не определилась — ничего не делается.

Все настройки — в `config.js`. **Перед установкой сверьте названия групп, состояний и типов работ с вашим YouTrack.**

## Установка

1. В проектах создать/привязать поля `Разработчик` и `Тестировщик` типа **user** (одно значение).
   Набор значений поля должен включать всех нужных пользователей (например, All Users),
   иначе запись пользователя вне набора приведёт к ошибке и откату изменения.
2. Собрать архив (из папки `TaskTrackers\YouTrack`):
   ```powershell
   Compress-Archive -Path .\dev-qa-fields\* -DestinationPath .\dev-qa-fields.zip -Force
   ```
3. YouTrack → Administration → Workflows → **Import workflow** → выбрать `dev-qa-fields.zip`.
4. Привязать workflow к нужным проектам (Attach to project) и убедиться, что все правила включены
   и нет предупреждений о неудовлетворённых requirements.

## Проверка

- Разработчик назначает задачу на себя → заполнено «Разработчик».
- Тимлид назначает задачу на тестировщика → заполнено «Тестировщик», «Разработчик» не меняется.
- В задачу без исполнителя QA списывает время → заполнено «Тестировщик».
- В задачу, где «Разработчик» уже заполнен, другой разработчик списывает время → поле не меняется.
- В проекте «Тестирование» пользователя вне групп назначают на задачу «В работе» → заполнено «Тестировщик».
