# Workflow: Разработчик / Тестировщик по задаче

Автоматически заполняет кастомные поля **Разработчик** и **Тестировщик**.

## Правила

| Файл | Когда срабатывает | Что делает |
|---|---|---|
| `set-on-assign.js` | Меняется Assignee (сам взял задачу или тимлид назначил), либо задача создаётся сразу с исполнителем | Пишет исполнителя в «Разработчик» или «Тестировщик» в зависимости от роли, если соответствующее поле **пустое** |
| `set-on-work-item.js` | В задачу списано время | Если соответствующее поле **пустое** — пишет туда автора списания |

Снятие исполнителя поля не очищает — история «кто делал» сохраняется.

## Когда заполняется поле

Поле заполняется, только если оно **пустое** и выполнены **все** условия его роли. Оба поля уже заполнены —
правила не срабатывают.

| Поле | Группа пользователя | Назначение: состояние задачи | Списание времени: состояние **или** тип работы |
|---|---|---|---|
| Разработчик | «Разработчики» | «В работе» | «В работе» или «Разработка» / «Реализация» |
| Тестировщик | «Тестировщики» | «В тестировании» | «В тестировании» или «Тестирование» |

Проект «Тестирование» (`PROJECT_STATES`, внутренний проект группы тестирования): «Разработчик» не заполняется,
«Тестировщик» — в состояниях «В работе» и «В тестировании».

Пользователь в обеих группах попадает в то поле, условия которого выполнены.

Все настройки — в `config.js`. **Перед установкой сверьте названия групп, состояний и типов работ с вашим YouTrack.**

## Установка

1. В проектах создать/привязать поля `Разработчик` и `Тестировщик` типа **user** (одно значение).
   Набор значений поля должен включать всех нужных пользователей
   (например, All Users или группы «Разработчики» / «Тестировщики»). Пользователя вне набора workflow
   не записывает: поле остаётся пустым, в лог workflow пишется предупреждение.
2. Собрать архив (из папки `TaskTrackers\YouTrack`):
   ```powershell
   Compress-Archive -Path .\autofill-dev-qa-fields\* -DestinationPath .\autofill-dev-qa-fields.zip -Force
   ```
3. YouTrack → Administration → Workflows → **Import workflow** → выбрать `autofill-dev-qa-fields.zip`.
4. Привязать workflow к нужным проектам (Attach to project) и убедиться, что все правила включены
   и нет предупреждений о неудовлетворённых requirements.

## Проверка

- Разработчик назначает на себя задачу «В работе» → заполнено «Разработчик».
- Задачу в другом состоянии (например, «Открыта») назначают на разработчика → ничего не заполняется.
- Тимлид назначает на тестировщика задачу «В тестировании» → заполнено «Тестировщик», «Разработчик» не меняется.
- Задачу «В работе» назначают на тестировщика (не в проекте «Тестирование») → ничего не заполняется.
- Пользователя вне обеих групп назначают на задачу «В работе» → ничего не заполняется.
- В проекте «Тестирование» тестировщика назначают на задачу «В работе» → заполнено «Тестировщик».
- В проекте «Тестирование» разработчика назначают на задачу «В работе» → ничего не заполняется.
- Тестировщик списывает время с типом «Тестирование» в задаче «В работе» → заполнено «Тестировщик».
- В задачу, где «Разработчик» уже заполнен, другой разработчик списывает время → поле не меняется.
