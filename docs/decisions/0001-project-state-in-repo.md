# 0001. Хранить состояние работы над проектом в репозитории

- **Статус:** принято
- **Дата:** 2026-10-12
- **Участники:** bj, Claude

## Контекст

Работа ведётся с нескольких машин и несколькими людьми. История сессий и память Claude Code
хранятся локально (`~/.claude/`) и привязаны к пути проекта на конкретной машине, поэтому
контекст теряется при смене машины или исполнителя.

## Решение

Состояние, идеи и решения хранятся в git: `CLAUDE.md`, `docs/STATUS.md`, `docs/ideas.md`,
`docs/decisions/`. Правила их ведения описаны в `CLAUDE.md`, который Claude читает автоматически.

## Альтернативы

- Синхронизация `~/.claude` между машинами — зависит от одинаковых путей, не решает проблему команды, есть риск утечки секретов.
- Облачные документы (Claude Docs, Notion) — не версионируются вместе с кодом.
- Трекер задач — можно использовать дополнительно для задач, но не для контекста и решений.

## Последствия

- Изменения в `docs/` проходят обычный цикл коммит/ревью.
- Возможны merge-конфликты в `STATUS.md` при параллельной работе — держать записи короткими, журнал дописывать строками в конец.
