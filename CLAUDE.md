# TaskTrackers

Скрипты, workflow и интеграции для систем управления задачами. Разделение — по типу трекера:

| Папка | Трекер | Что внутри |
|---|---|---|
| `YouTrack/` | YouTrack | Workflow-скрипты (`autofill-dev-qa-fields` — автозаполнение полей «Разработчик» / «Тестировщик»); `yt/` — работа Claude с YouTrack через API |
| `Jira/` | Jira | _запланировано_ |

Новый трекер — новая папка верхнего уровня со своим `CLAUDE.md` (специфика трекера: как собирать, куда
устанавливать, что сверять). Общее для всех трекеров — в этом файле и в `docs/`.

## Общий контекст проекта

Над проектом работают несколько человек с разных машин. Локальная история и память
Claude Code между машинами **не переносятся**, поэтому всё состояние работы хранится в репозитории:

| Файл | Назначение |
|---|---|
| `docs/STATUS.md` | Текущее состояние по всем трекерам: в работе, следующие шаги, блокеры |
| `docs/journal-YYYY-MM.md` | Журнал: дата, кто/машина, что сделано |
| `docs/ideas.md` | Бэклог идей, ещё не взятых в работу |
| `docs/decisions/` | Принятые решения (ADR), по одному файлу на решение |

## Правила работы для Claude

- **В начале сессии** — `python <AI-Memory>/tools/status_tool.py brief .` (остальное в `docs/STATUS.md`, журнал и `docs/ideas.md` — по задаче).
- **В конце значимого шага** обновить `docs/STATUS.md`: что сделано, что дальше; журнал — `python <AI-Memory>/tools/status_tool.py log . "кто/машина" "что сделано"`, без чтения файла. В задачах и журнале указывать трекер (`[YouTrack]`, `[Jira]`).
- **Принято архитектурное или процессное решение** → новый файл `docs/decisions/NNNN-краткое-название.md`
  по шаблону `docs/decisions/0000-template.md`, ссылка на него в `STATUS.md`.
- **Появилась идея, не относящаяся к текущей задаче** → добавить в `docs/ideas.md`, а не реализовывать сразу.
- Состояние проекта не сохранять в локальную память Claude — только в эти файлы.
- Изменения в `docs/` коммитить вместе с кодом, к которому они относятся.
